# HANDOFF — проект MOEX ISS / Эллиотт (любой инструмент, основной — USDRUBF)

Документ для передачи проекта другому агенту. Описывает, что сделано, как это
устроено, какие правила действуют и что осталось сделать.

## 1. Назначение

- Получать котировку и свечи **любого инструмента** Московской биржи из ISS. Основной инструмент
  пользователя — фьючерс **USDRUBF** (FORTS); для него CLI работает по умолчанию.
- Строить вспомогательный анализ: MA50/200, RSI14, ATR14, зигзаг, уровни,
  кандидаты разметки по Эллиотту.
- Рисовать графики 1ч и 1д (SVG и PNG) с разметкой волн и уровнями плана.
- Каждое утро в **08:07 МСК** присылать пользователю в этот чат торговые сводки по **USDRUBF и IMOEXF**:
  волновой счёт, уровни, графики, план ЛОНГ / ШОРТ / ЖДАТЬ.

Стек: только стандартная библиотека, Python 3.10+. Ключ API не нужен.
Данные ISS приходят с задержкой около 15 минут, пользователя это устраивает.
Все времена указаны по МСК (`Europe/Moscow`).

## 3. Модули

### moex.py — клиент ISS
- Константы:
  - `ISS_BASE="https://iss.moex.com/iss"`;
  - `DEFAULT_SECID="USDRUBF"`;
  - `ISS_PAGE=500` (размер страницы пагинации).
- Классы данных:
  - `Candle(begin, open, high, low, close, volume)`;
  - `Board(engine, market, board, decimals)`;
  - `Quote(secid, board, last, bid, offer, open, high, low, settle_price, change_pct, open_interest, volume_today, last_trade_time, system_time, trade_date, source, engine, market, decimals)`, у него есть свойство `delay_minutes`.
- `MoexClient(secid, engine=None, market=None, board=None, timeout=20, retries=3)`:
  - `resolve()` при первом обращении запрашивает `securities/{SECID}.json?iss.only=boards`, фильтрует по заданным engine/market/board и берёт `is_primary`, затем `is_traded`. Неизвестный тикер → `MoexError("Инструмент … не найден на MOEX")`;
  - все запросы идут по пути `engines/{e}/markets/{m}/boards/{b}/securities/{SECID}`;
  - `_get` повторяет запрос с паузами 1, 2 и 4 с, после чего бросает `MoexError("ISS недоступен: …")`;
  - `get_quote()` бросает `MoexError`, если marketdata пустая. Цена — `LAST`, у индексов `CURRENTVALUE`; изменение — `LASTTOPREVPRICE` или `LASTCHANGEPRC`; торговая дата — `TRADEDATE` или `SYSTIME[:10]`;
  - `get_candles(interval, start, end)` принимает только интервалы ISS: 1, 10, 60, 24 (день), 7 (неделя), 31 (месяц), 4 (квартал);
  - `get_candles_minutes(minutes, …)`:
    - 1, 10 и 60 минут берутся из ISS напрямую;
    - интервалы меньше 60 минут собираются из минуток;
    - интервалы, кратные 60, собираются из часовых свечей;
  - `recent(minutes, days)`.
- `resample` выравнивает корзины от полуночи.

### analysis.py
- Индикаторы: `sma`, `rsi` и `atr` (оба по Уайлдеру).
- `zigzag`: порог по умолчанию 2×ATR, последний экстремум не подтверждён.
- `levels(pivots, price, tolerance, limit=3)`: допуск 0.5×ATR, возвращает сопротивления и поддержки.
- `check_impulse` проверяет три обязательных правила:
  - волна 2 не заходит за начало импульса;
  - волна 3 не самая короткая;
  - волна 4 не перекрывает волну 1.

  Возвращает соотношения волн, инвалидацию и заметки (диагональ, усечённая 5-я).
- `check_abc`: C должна выйти за A.
- `wave_candidates`: импульс строится по последним 6 экстремумам, ABC — по последним 4.
- `snapshot(timeframe, candles)` собирает всё в `WaveCheck` / снимок.

### report.py
- `STALE_MINUTES=20`. Если данные старше, сводка пишет «НЕ является текущей».
- `collect(client, days_1h=30, days_1d=400)`:
  - свечи 1ч берутся из часовых ISS, незакрытый час достраивается из минуток (`merge_tail`);
  - свечи 1д берутся из дневных ISS, текущий день в них уже есть.
- `time_format(s)`: для 1д время выводится только датой (в сводке и на оси графика).
- `render` выдаёт Markdown: заголовок по тикеру, рынок `engine/market`, цены с точностью `quote.decimals`. Расчётная цена и ОИ выводятся только для фьючерсов. `to_json(last=100)` — JSON с ключами `quote`, `h1`, `d1`.

### chart.py
- Холст 960×540, справа поле 170 px под подписи.
- Цвета:
  - свеча вверх #1e9e6a, вниз #d64545;
  - MA50 #e08a00, MA200 #7b4fc9;
  - волны #1f5fbf.
- `render_svg(s, last=80, levels=None, waves=None, title="", decimals=2)`. CLI передаёт заголовок «ТИКЕР · ТФ · MOEX ISS» и точность инструмента.
- Уровень инвалидации рисуется серым пунктиром "2 3".

## 4. CLI

Глобальные флаги ставятся до подкоманды: `--secid` (по умолчанию USDRUBF), `--engine`, `--market`, `--board`.
Ошибки ISS выводятся одной строкой `Ошибка: …` в stderr, код выхода 2.

```
python3 -m usdrubf quote                     # JSON
python3 -m usdrubf candles -t 60 --from YYYY-MM-DD [--till …]   # CSV; 1440 → дневки
python3 -m usdrubf report [--json] [-o FILE]
python3 -m usdrubf chart [-t 60|1440]... [--last N] [--level P:Подпись[:цвет]]... \
        [--waves 60=0,1,2,3,4,5]... [-o charts] [--png]
python3 -m unittest discover -s tests
```

- Цвет уровня задаётся словом red, green, blue, gray, orange или кодом `#rrggbb`.
- Если задан хотя бы один `--level`, автоматические уровни не рисуются.
- PNG получается первым сработавшим способом: Playwright Chromium, `rsvg-convert`, ImageMagick `convert`.
- Файлы сохраняются как `charts/{secid строчными}_1h.*` и `charts/{secid строчными}_1d.*`. По умолчанию показывается 120 часовых и 160 дневных свечей.

## 5. Промпт и навыки

- `prompts/moex_elliott.md` — универсальный промпт, тикер подставляется вместо `{SECID}`. Разделы 0–9:
  - 0 — данные и команды;
  - 1 — роль: рабочий ТФ 1ч, подтверждение на 1д;
  - 2 — правила данных;
  - 3 — Эллиотт;
  - 4 — теханализ;
  - 5 — сигнал ЛОНГ / ШОРТ / ЖДАТЬ;
  - 6 — расчёт сделки, желательно R/R ≥ 1:2;
  - **7 — формат ответа (короткий, на один экран)**: заголовок с датой, цена и статус, что изменилось, волны, уровни, одна таблица плана, одно действие;
  - 8 — взаимодействие;
  - 9 — приоритеты.
- `prompts/usdrubf_elliott.md` — только особенности USDRUBF: вечный фьючерс RFUD, не спот и не Si, есть расчётная цена и ОИ, клиринги.
- Навык `.claude/skills/moex-elliott/SKILL.md` (аргумент — тикер). Сбор данных (шаг 1) и графики (шаг 4)
  делегируются субагентам (Agent, general-purpose, `run_in_background: false`; по нескольким тикерам —
  параллельно). Главный агент делает только анализ и текст. Если Agent недоступен, команды выполняются
  напрямую. Шаги:
  1. Субагент «данные» выполняет `quote` и `report --json` с `--secid` и возвращает факты без анализа. Свежесть и тикер проверяет главный агент.
  2. Сделать основной и альтернативный волновой счёт, для каждого указать инвалидацию и уверенность.
  3. Определить уровни с точностью инструмента.
  4. Субагент «графики» выполняет `chart --png …` (отмена — gray) и возвращает пути. Главный агент отправляет картинки через `SendUserFile`: сначала 1d, потом 1h (`status: proactive`, `display: render`).
  5. Написать короткую сводку по разделу 7 (с блоком «Что изменилось»).
- Навык `.claude/skills/usdrubf-morning/SKILL.md` — тонкая обёртка: `moex-elliott` с тикерами USDRUBF и IMOEXF (по сводке на каждый). Его вызывает утренняя задача.

## 6. Расписание

- Запланированная задача **`trig_01STDGw9WHKrMoBDvt2bKzJ2`** с расписанием `CRON_TZ=Europe/Moscow 7 8 * * *`.
- Срабатывает в эту же сессию (этот чат) и запускает навык `usdrubf-morning`.
- В репозитории задача не хранится. Чтобы перенести её в другую сессию, создайте новую задачу через `create_trigger` с тем же cron и промптом «утренняя сводка по навыку usdrubf-morning».

## 7. Постоянные правила пользователя (дословно)

- «Если ISS недоступен или цена неактуальна — так и напиши, статус ЖДАТЬ, графики не строй.»
- «Учитывай открытые позиции, только если я о них сообщал.» На сейчас пользователь ни о каких позициях не сообщал.
- Во время сводки ничего не коммитить, не пушить и не создавать PR.
- Сводку присылать в этот чат.
- Отвечать по-русски.

## 8. Известные нюансы

- Тесты не покрывают: живую сеть, повторы запросов, CLI `main`, `to_png`.
- Соединение с ISS иногда сбрасывается (Connection reset). Клиент делает 3 попытки; если не помогло — `Ошибка: ISS недоступен`, по правилам статус ЖДАТЬ.
- Пакет по историческим причинам называется `usdrubf`, хотя работает с любым тикером. Его не переименовывали, чтобы не ломать утреннюю задачу и навыки.
- Автоматическая волновая разметка вспомогательная: последний экстремум зигзага не подтверждён, окончательный счёт делает агент.
- Проверено вживую: USDRUBF (futures/forts/RFUD), SBER (stock/shares/TQBR), CNYRUB_TOM (currency/selt/CETS, 4–5 знаков), IMOEX (stock/index/SNDX, без bid/offer и объёма).
