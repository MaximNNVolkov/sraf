# MOEX — многодневные торговые планы на данных T-Invest

Цены и свечи по умолчанию поступают из T-Invest API. Нужен `TINKOFF_TOKEN`
в окружении или локальном `.env`. Python 3.10+, только стандартная библиотека.
ISS доступен явно через `--source iss`; без авторизации его данные задержаны.

Для IMOEXF и USDRUBF: утром анализ режима и сохранение плана на 3–20 торговых дней,
затем контроль в 12:01, 16:01 и 20:01 МСК. W1 задаёт режим, D1 — направление,
H4 — подтверждение сетапа. H1 используется только для точного пробоя/ретеста.
Подробные правила, горизонты истории и ограничения: [docs/STRATEGY.md](docs/STRATEGY.md).

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

```
.venv/bin/python -m usdrubf quote                       # биржевая последняя цена и время сделки (JSON)
.venv/bin/python -m usdrubf candles -t 15 --from 2026-10-01   # свечи CSV: 1/5/10/15/30/60/240 мин, 1440 — день
.venv/bin/python -m usdrubf report                      # контекст 1н/1д/4ч/1ч; --intraday — прежние 15м/1ч
.venv/bin/python -m usdrubf chart --png               # графики 4ч и 1д (SVG + PNG); -t 10080 — недельный
.venv/bin/python -m usdrubf chart --png --waves 240=0,A,B,C --level 80.90:"вход 80.90":blue --level 81.20:"стоп 81.20":gray
.venv/bin/python -m usdrubf --secid SBER report          # любой тикер: SBER, CNYRUB_TOM, IMOEX, SiZ6…
.venv/bin/python -m usdrubf --source iss --secid SBER --board SMAL quote   # явно заданный режим торгов
.venv/bin/python -m unittest discover -s tests          # тесты (без сети)
.venv/bin/python -m usdrubf trade migrate OPEN_POSITIONS.md  # однократная миграция старого журнала
.venv/bin/python -m usdrubf trade list                       # открытые позиции из trading.db
```

## Воспроизводимый бэктест направления D1

```sh
.venv/bin/python scripts/moex_direction_backtest.py
# воспроизводимый срез (дата --as-of сама не включается):
.venv/bin/python scripts/moex_direction_backtest.py --as-of 2026-11-18 --tests 30
# повторная генерация без сети из проверенного CSV-кэша:
.venv/bin/python scripts/moex_direction_backtest.py --offline
```

Скрипт скачивает только дневные свечи IMOEXF и USDRUBF из MOEX ISS, исключает
дату `--as-of` и более поздние как потенциально незавершённые (`--as-of` нельзя
задавать позже текущей московской даты; по умолчанию это сегодня), фиксирует
исходные CSV и их SHA-256 в
`reports/moex_backtest_data/`, а HTML пишет в `reports/moex_direction_backtest.html`.
Параметры по умолчанию: два календарных года, 30 случайных валидных дат на тикер,
seed `20261118`. Сначала по данным не позже `t` строится список кандидатов с
ненейтральным прогнозом, затем для каждого тикера выполняется выборка отдельным
derived seed, и лишь после неё читается факт `t+1`. Нейтральный факт не исключается:
он остаётся «нейтрально» и считается ошибкой прогноза UP/DOWN. HTML фиксирует
eligible/excluded counts, derived seeds, время загрузки, ISS URL, SHA-256 CSV и
скрипта, Python и точную команду. Общая точность двух тикеров только описательная,
без предположения независимости и без совместного доверительного интервала. При
сетевой ошибке данные не подменяются и отчёт не перезаписывается.

## Структурированный торговый процесс

- `usdrubf/trading.py` — SQLite-журнал сделок, расчёт P/L, один торговый план на тикер и постоянный автомат состояний (`WAITING → CROSSED → HOURLY_CONFIRMED → RETEST_CONFIRMED → ACTIVE → TP1/TP2/STOPPED/CANCELLED`).
- `usdrubf/process.py` — факты 1н/1д/4ч/1ч и проверка событий; `usdrubf/agent.py` — обратный канал, валидация и квитанции. Агент сам выбирает торговый сценарий.
- Каноническое состояние хранится в `trading.db`; `OPEN_POSITIONS.md` — генерируемое представление. Денежный P/L не рассчитывается без явно известной стоимости пункта.
- Сценарий автоматически отклоняется, если нет TP2 или R/R до TP2 ниже 1:2. Пересечение уровня не считается входом без закрытия часовой свечи; если план требует ретест, вход активируется только после ретеста.
- При открытой позиции новый сценарий входа по тому же тикеру блокируется: монитор отдельно показывает рыночный план и фактическую позицию.

- `usdrubf/tbank.py` — основной клиент T-Invest: биржевые цены, нативные свечи, завершённость баров, шаг цены и статус торгов.
- `usdrubf/moex.py` — дополнительный клиент ISS (`--source iss`): выбор режима торгов, котировка (для индексов — значение индекса), свечи с пагинацией, ресемплинг
  (ISS отдаёт 1, 10, 60 мин и дни; 15 мин собираются из минуток).
- `usdrubf/analysis.py` — MA, RSI14 (Уайлдер), ATR14, зигзаг-экстремумы, уровни,
  проверка обязательных правил Эллиотта и соотношений волн.
- `usdrubf/report.py` — контекст 1н/1д/4ч/1ч; прежний подробный отчёт 15м/1ч доступен с `--intraday`.
- `usdrubf/chart.py` — SVG-график: свечи, MA50/MA200, зигзаг с подписями волн, уровни плана.
  `--waves ТФ=…` подписывает последние экстремумы зигзага, `--level ЦЕНА:ПОДПИСЬ[:ЦВЕТ]` рисует уровни
  (если задан хотя бы один — автоуровни не рисуются). PNG — через headless Chromium, rsvg-convert или ImageMagick.
- `prompts/moex_elliott.md` — промпт торгового агента для любого тикера (`{SECID}`);
  `prompts/usdrubf_elliott.md` — особенности USDRUBF.
- Навыки: `.claude/skills/moex-elliott` — сводка по любому тикеру; `.claude/skills/usdrubf-morning` —
  утренняя сводка USDRUBF (обёртка над `moex-elliott`).
- `docs/HANDOFF.md` — описание проекта для передачи другим агентам.

Ограничения: без авторизации ISS отдаёт данные с задержкой ~15 минут — сводка
всегда показывает время последней сделки. Все времена — МСК. Автоматическая
волновая разметка вспомогательная: последний экстремум зигзага не подтверждён.

## Утренний план и контроль по H4

```sh
.venv/bin/python scripts/moex_imoexf_tf.py
.venv/bin/python scripts/moex_usdrubf_tf.py
.venv/bin/python scripts/moex_monitor_tf.py
.venv/bin/python scripts/tf_report.py USDRUBF  # только контекст, не сохраняет план
```

Монитор новых планов не создаёт. Активный сценарий сохраняется между днями.
Факт сделки определяется по брокеру, а не по статусу сценария.
План до открытия торгов может использовать явно помеченную цену последней сессии.
Численные фильтры новой стратегии ещё требуют исторической проверки.

## Обратная связь от агента

Утренний скрипт больше не выбирает точку входа: выдаёт снимок и `AWAITING_AGENT`.
Hermes анализирует данные, отправляет план через
`scripts/moex_agent_plan.py submit --file PATH` и проверяет его через `get --ticker TICKER`.
Только `ACCEPTED` означает сохранение; `REJECTED` содержит ошибки.
Контракт и пример: [docs/AGENT_PROTOCOL.md](docs/AGENT_PROTOCOL.md).
