# Конструктор слайдов: принцип

Скил описывает механику, а не внешний вид. Подходит для любой одностраничной HTML-презентации. Имена классов ниже — пример: переименуй под свой проект, но сохрани структуру.

## 1. Модель данных — сам DOM

Отдельной JSON-модели нет: состояние презентации и есть её разметка. Отсюда три следствия: сохранить = записать HTML, загрузить = открыть файл, агент правит презентацию обычным редактированием HTML.

```
#stage                          контейнер всех слайдов
└─ section.slide                слайд; порядок в DOM = порядок показа
   ├─ header > h2               заголовок
   └─ .blocks                   контейнер элементов (одна или две колонки)
      └─ .blk[data-type=X]      элемент; тип = ключ в реестре
         └─ …разметка типа X…   повторяющиеся пункты внутри
```

Слайд-конструктор помечается отдельным классом (например `section.slide.free`). Тогда рядом могут жить слайды с ручной вёрсткой, и инструменты конструктора работают только на «свободных» слайдах.

Параметры хранятся атрибутами прямо на узлах, чтобы переживать сохранение:

| Что | Где | Пример |
|---|---|---|
| тип элемента | `.blk` | `data-type="cards"` |
| вариант/акцент | `.blk` | `data-tone="green"` |
| раздел/подпись слайда | `section` | `data-section="Часть 2"` |
| фон слайда | `section` | `data-bg="dark"`; фото: `data-bg="photo"` + inline `background-image` |
| ширина элемента | `.blk` | `style="width:70%"` |
| две колонки | `.blocks` | `class="blocks two" style="--split:60%"` |
| ширина колонок сетки | внутренний контейнер | `style="grid-template-columns:minmax(0,1.4fr) minmax(0,1fr)"` |
| ширина столбцов таблицы | `th` первой строки | `style="width:30%"` |

Не используй для CSS-переменных имена, которые уже зарегистрированы через `@property` с другим типом: значение молча станет невалидным.

## 2. Реестр элементов

Все типы элементов описаны в одном объекте. Это единственный источник разметки и для кнопок панели, и для агента, который правит файл:

```js
const BLOCKS = {
  text:  { html: '<p class="lead">Текст</p>' },
  cards: { item: '.card', tone: 1,
           html: '<div class="cards">' + rep(3, i => `<div class="card"><h3>Карточка ${i}</h3><p>Текст</p></div>`) + '</div>' },
  table: { item: 'tr', cols: 1, html: '<table><tr><th>A</th><th>B</th></tr><tr><td>…</td><td>…</td></tr></table>' },
  photo: { item: 'figure', html: '<div class="gal"><figure><div class="photo"></div><figcaption><h3>Подпись</h3></figcaption></figure></div>' },
};
```

- `html` — стартовая разметка с текстами-заглушками.
- `item` — селектор повторяющегося пункта: включает «＋/− пункт».
- `tone` — у элемента есть варианты акцента.
- `cols` — у таблицы можно добавлять и убирать столбцы.

Новый тип = новая запись в реестре + кнопка `<button data-add="тип">` в панели (+ при необходимости селектор сетки в список для ручек ширины колонок). Остальной код не меняется.

## 3. Операции

Каждая операция — это простое изменение DOM. После любой из них ставь флаг `dirty = true` и вызывай подгонку слайда (раздел 5).

| Операция | Реализация |
|---|---|
| новый слайд | создать `section.slide.free` с `header` + пустым `.blocks`, вставить **после текущего**, пересчитать список слайдов, перейти на него, поставить фокус в заголовок |
| удалить слайд | `confirm()` → `remove()` → пересчитать → перейти на соседний |
| добавить элемент | `div.blk[data-type]` с `innerHTML = BLOCKS[type].html` → `append` в `.blocks` текущего слайда → навесить управление → включить редактирование |
| ＋ пункт | клонировать последний `item`, очистить клон от одноразового состояния (фото, выделение) → `after` |
| − пункт | удалить последний `item`, но не единственный |
| ＋/− столбец | клонировать/удалить последнюю ячейку в каждой `tr`, минимум 2 столбца; сбросить ширины `th` |
| вверх/вниз | `prev.before(blk)` / `next.after(blk)` |
| удалить элемент | `blk.remove()` |
| акцент | циклически перебирать `data-tone` по списку вариантов, пустое значение = по умолчанию |
| колонки | переключать класс `two` на `.blocks` |
| фон | менять `data-bg` на слайде; «ко всем слайдам» копирует `data-bg` и `backgroundImage` текущего на все |

Номера слайдов, счётчики и навигацию **не хранить в разметке**. Пересчитывай их функцией `reindex()` после каждого добавления или удаления: `slides = [...querySelectorAll('.slide')]`, затем перегенерируй служебные подписи.

## 4. Режим правки

- Переключатель (клавиша `E` + кнопка) ставит класс `editing` на `body`. Все инструменты видны только через CSS `body.editing …`, в показе их нет.
- Текст правится через `contenteditable` на «листовых» текстовых узлах: `h1–h4, p, li, td, th, figcaption…`, у которых нет вложенных блоков. Атрибут ставится при входе в режим и снимается при выходе. Новые узлы (элемент, клон пункта, слайд) размечаются сразу при создании.
- Управление элементом (`.blk-ctl`: ＋ − ↑ ↓ акцент ✕) создаётся скриптом при загрузке и при добавлении. В исходной разметке его нет.
- `mousedown` на панелях вызывает `preventDefault()`, чтобы клик по кнопке не сбрасывал фокус и выделение в тексте.
- Клик по рамке фото открывает скрытый `<input type=file>`. Ещё можно перетащить файл. Картинка уменьшается на `<canvas>` (до ~1600–1920px, JPEG) и вписывается как `data:`-URL: файл должен работать офлайн.
- Режим правки должен включаться с любого экрана, включая заставку и стартовый экран: вход в правку снимает их.

## 5. Подгонка под кадр

Слайд имеет фиксированный кадр, а контента у конструктора может быть сколько угодно.

- `.blocks` занимает оставшуюся высоту кадра. Если `scrollHeight > clientHeight`, уменьшай `zoom` (или `transform: scale`) итеративно: `z *= clientHeight/scrollHeight*0.99`, 2–3 прохода, с нижней границей (~0.35).
- Размеры шрифтов внутри элементов — через container queries (`container-type:inline-size` + `cqi` в `clamp/min/max`). Тогда элемент, ужатый по ширине (колонка, ручка ширины), сам уменьшает текст.
- У сеток — `minmax(0, …)`, у таблиц — `table-layout:fixed`, иначе длинное слово распирает колонку за край.
- Подгонку вызывай после каждой операции, при смене слайда и при `resize`.

## 6. Ручки ширины

Ручки — абсолютно спозиционированные узлы `.rz` внутри `.blk` (или `.blocks`), видимые только в режиме правки:

- **ширина элемента** (ручка у правого края): `width = (w0 + 2·dx) / ширина_родителя`, от 20% до 100%. Элемент центрируется `margin-inline:auto`, поэтому `dx` умножается на 2. При значении ~100% атрибут снимается.
- **граница двух колонок** (ручка на `left: var(--split)`): `--split` от 20% до 80%.
- **колонки сетки/таблицы** (ручка между соседними ячейками): меняются только две соседние ширины, их сумма постоянна, у каждой есть минимум (8–12%). Сетка записывается в `fr`, таблица — в `%` на `th`.
- Ручки между ячейками ставятся по фактическим `getBoundingClientRect()` ячеек. Если у слайда есть `zoom`/`scale`, дели координаты на коэффициент `rect.width / computed width`.
- Перетаскивание идёт через `pointerdown` (в фазе захвата, чтобы не сработало перелистывание) + `setPointerCapture`. Двойной клик сбрасывает: атрибут удаляется.
- Если после ＋/− пункта число колонок не совпадает с сохранённым шаблоном сетки, шаблон нужно сбросить.

## 7. Сохранение

Сохраняется клон всего документа, очищенный от служебного:

```js
const root = document.documentElement.cloneNode(true);
root.querySelectorAll('[contenteditable]').forEach(e => e.removeAttribute('contenteditable'));
root.querySelectorAll('.blk-ctl, .rz, /* прочие служебные */').forEach(e => e.remove());
root.querySelectorAll('.slide').forEach(s => s.classList.remove('active' /*, состояния показа */));
root.querySelector('body').removeAttribute('class');           // снять editing и т.п.
// анимированные значения вернуть к финальным, inline-стили анимаций убрать
const blob = new Blob(['<!DOCTYPE html>\n' + root.outerHTML], { type: 'text/html' });
```

Затем `showSaveFilePicker` (Chrome/Edge), а при отказе или отсутствии API — скачивание через `<a download>`. Горячая клавиша — Ctrl/Cmd+S. При несохранённых правках (`dirty`) показывай предупреждение в `beforeunload`.

Правило: всё, что скрипт создаёт сам, либо пересоздаётся при загрузке, либо удаляется при сохранении. В файл попадает только содержимое и атрибуты-параметры из раздела 1.

## 8. Движок отдельно от слайдов

Держи стили и скрипт отдельно от содержимого `#stage`, так чтобы границы контейнера находились простым поиском строки. Тогда:

- **шаблон** = тот же движок + титульный слайд + один пустой конструктор;
- **обновление движка** в уже наполненной копии = взять `#stage` из копии, а всё остальное из свежей сборки;
- **автономность**: шрифты и картинки встраиваются base64 при сборке, внешние CDN не нужны.

## 9. Агенту: правка презентации кодом

1. Найди реестр `BLOCKS` и бери разметку элементов только оттуда. Меняй тексты, а структуру и классы оставляй.
2. Новый слайд — копия пустого конструктора в нужном месте `#stage`. Его `.blocks` заполняется `.blk[data-type]`.
3. Параметры (ширины, колонки, фон, акцент) задавай атрибутами из таблицы раздела 1.
4. Не вписывай служебные узлы, состояния показа и номера: их создаёт скрипт.
5. Если у анимированного значения есть копия в атрибуте (например `data-final`), меняй оба.
6. Если есть сборка, пересобери. Проверь в headless-браузере:
   - нет `pageerror`;
   - коэффициент подгонки не ниже ~0.6, иначе раздели контент на два слайда;
   - `scrollWidth <= clientWidth` у контейнера элементов;
   - в сохранённой копии нет служебных узлов и `contenteditable`.
