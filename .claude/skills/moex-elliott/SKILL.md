# Сводка по инструменту MOEX

Аргумент навыка — тикер MOEX (`SECID`). Если его нет, возьми тикер из запроса пользователя. Если
тикер неоднозначен, задай один уточняющий вопрос (например, «Si» — это квартальный SiZ6 или вечный
USDRUBF?). Ниже `$S` — тикер.

Отвечай на русском. Цены не выдумывай: всё берётся из MOEX ISS через `python3 -m usdrubf --secid $S …`
(данные с задержкой ~15 мин). «ЖДАТЬ» — нормальный результат.

- Методология и формат — `prompts/moex_elliott.md` с `{SECID}` = `$S`, раздел 7 обязателен.
- Если есть `prompts/<тикер строчными>_elliott.md`, прочитай его: там особенности инструмента.

## Распределение работы

Сбор данных (шаг 1) и построение графиков (шаг 4) **делегируй субагентам** через инструмент Agent
(`subagent_type: general-purpose`). Сам делай только анализ: волны, уровни, план и текст сводки.

- Ждать нужно результат субагента, поэтому вызывай его с `run_in_background: false`.
- Субагент начинает без контекста. В промпте укажи всё: каталог репозитория, точные команды, формат ответа.
- Отчёт субагента пользователь не видит. Нужные факты переноси в сводку сам, а картинки отправляй сам через SendUserFile.
- Если тикеров несколько, запускай субагентов по разным тикерам параллельно, в одном сообщении.
- Если инструмента Agent нет или субагент упал, выполни те же команды сам и коротко отметь это в сводке.
- Цифры из отчёта субагента не дополняй и не округляй. Чего нет в отчёте, того нет в данных.

## 1. Данные и проверка актуальности (субагент «данные»)

Задание субагенту: «В корне репозитория выполни

```bash
python3 -m usdrubf --secid $S quote
python3 -m usdrubf --secid $S report --json
```

и верни:

- полный JSON `quote` без изменений;
- текущее время МСК (`TZ=Europe/Moscow date`);
- задержку последней сделки в минутах;
- по таймфреймам 1h и 1d (ключи `h1` и `d1` в JSON): close, MA50, MA200, RSI14, ATR14, последние 10 экстремумов зигзага (время, цена, H/L), уровни сопротивления и поддержки, кандидаты разметки с проверкой правил и уровнем отмены, последние 12 свечей.

Если команда завершилась ошибкой, верни её текст дословно. Ничего не анализируй и не дописывай от себя.
Файлы не меняй, не коммить».

Проверку по ответу делаешь сам:

- Рынок и режим определяются автоматически (основной режим в ISS) и выводятся в `quote`
  (`engine`, `market`, `board`). Если нужен другой режим, добавь `--engine/--market/--board`
  перед подкомандой во все команды.
- «Инструмент … не найден на MOEX» означает неверный тикер. Так и скажи, предложи проверить тикер,
  статус ЖДАТЬ.
- Сверь время последней сделки с текущим временем МСК. Учитывай задержку ~15 мин, выходные,
  перерывы и расписание сессий этого рынка.
- **Если ISS недоступен или цена неактуальна — так и напиши, статус ЖДАТЬ, графики не строй.**
  На этом сводка заканчивается.

## 2. Разметка волн

- По данным `report` (зигзаг 2×ATR, MA50/200, RSI14, ATR14) посчитай волны на 1h (рабочий) и на 1d (старший).
  При необходимости смотри свечи: `python3 -m usdrubf --secid $S candles -t 60 --from ГГГГ-ММ-ДД`.
- Проверь правила:
  - волна 2 не заходит за начало волны 1;
  - волна 3 не самая короткая;
  - волна 4 не заходит в зону волны 1;
  - соотношения Фибоначчи.
- Дай основной и альтернативный счёт, уровень отмены каждого и уверенность.
- Явно разделяй подтверждённое и гипотезу.

## 3. Уровни

Выбери сопротивления, промежуточный уровень, поддержки и уровень отмены. Опирайся на кластеры
уровней из `report`, экстремумы волн и MA. Цены пиши с точностью инструмента (`decimals` в `quote`).

## 4. Графики (субагент «графики»)

Подставь в команду свою итоговую разметку и уровни. Задание субагенту: «В корне репозитория выполни
ровно эту команду и верни пути созданных PNG и SVG (или текст ошибки дословно). Ничего больше не делай,
файлы вне `charts/` не меняй, не коммить:

```bash
python3 -m usdrubf --secid $S chart --png -o charts \
  --waves 60=<точки волн 1h> --waves 1440=<точки волн 1d> \
  --level <цена>:Отмена:gray --level <цена>:Сопротивление:red --level <цена>:Поддержка:green ...
```
»

- Цвета уровней:
  - сопротивление и стоп — red;
  - поддержка и цели — green;
  - вход — blue;
  - отмена — gray.
- Если задан хоть один `--level`, автоуровни не рисуются, поэтому передай все нужные уровни.
- Субагент вернёт пути `charts/<тикер строчными>_1h.png` и `_1d.png`. Если PNG не создан, сводку
  отправь без картинок и напиши об этом.
- Отправь картинки сам через SendUserFile **до** текста сводки, сначала 1d, потом 1h (`status: proactive`, `display: render`).

## 5. Текст сводки (раздел 7)

Коротко, на один экран, строго по разделу 7 `prompts/moex_elliott.md`:

1. Заголовок `$S — ДД.ММ, ЧЧ:ММ МСК`, цена (время сделки, задержка), статус ЛОНГ / ШОРТ / ЖДАТЬ.
2. **Что изменилось**: 1–2 предложения по сравнению с прошлой сводкой по тикеру в чате
   (цена, структура, сработали ли условия). Если её нет, так и напиши.
3. **Волны**: основной и альтернативный счёт, по пункту на каждый — разметка, уверенность, цели, отмена.
4. **Уровни**: сопротивление и поддержка одной строкой каждое.
5. **План сделки**: одна таблица (Сделка, Когда входить, Вход, Стоп, Цели, R/R). Если сигнал
   не подтверждён, не подставляй выдуманные цены, а укажи условие.
6. **Действие**: одно конкретное действие.

Индикаторы, проверку правил по пунктам и служебные пояснения (как считал, ветки, коммиты) в сводку
не включай — только если пользователь спросит или что-то сломалось.

Для нескольких тикеров сделай отдельную сводку по каждому. Субагентов «данные» запускай по всем тикерам сразу, затем анализируй и строй графики по каждому тикеру.

## Ограничения

- Открытые позиции учитывай, только если пользователь о них сообщал.
- По индексам (IMOEX, RTSI) сделки напрямую невозможны. План давай как ориентир для фьючерса или фонда
  на индекс и прямо об этом пиши.
- Во время сводки ничего не коммить, не пушь и не открывай PR.
