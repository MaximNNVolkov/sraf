# Слайды «Кино»: принцип конструктора

Презентация — один HTML-файл. Все слайды лежат подряд внутри `<div id="stage">` … `</div>` (сразу за ним идёт `<div id="grain"`). Скрипт в конце файла сам находит слайды, нумерует их, навешивает режим правки и подгоняет размер. Агенту нужно только написать правильную разметку. JS при этом трогать не надо.

## Где что лежит

| Файл | Что это | Правим? |
|---|---|---|
| `kino/src/deck.html` | Исходник основной презентации: CSS, слайды, панель, JS | Да |
| `kino/src/template.html` | Только слайды чистого шаблона (титул + пустой конструктор) | Да |
| `kino/build.mjs` | Сборка: встраивает шрифты; шаблон = `deck.html`, у которого содержимое `#stage` заменено на `template.html` | Нет |
| `kino/strategic-session-kino.html`, `kino/template-kino.html` | Результат сборки | Нет, только пересобрать |
| `kino/upgrade.mjs` | Переносит слайды из сохранённой копии в свежий движок | Нет |
| `*-правки.html`, `*_with-photos.html` | Копии пользователя (Ctrl+S), со встроенными фото | Только по просьбе |

После любой правки в `src/` выполни `node kino/build.mjs`. Копию пользователя обнови так: `node kino/upgrade.mjs копия.html [итог.html]`. Скрипт берёт `#stage` из копии, а всё остальное из сборки.

## Слайд

```html
<section class="slide [вариант]" data-act="Акт II · Название акта" [data-noslate]>
  …содержимое…
</section>
```

- Порядок слайдов задаётся порядком `<section>` в `#stage`. Номера «Сцена NN» не пишутся руками: `reindex()` генерирует их при загрузке в `.slate`.
- `data-act` — подпись акта на хлопушке слайда. Слайды одного раздела получают одинаковое значение.
- `data-noslate` убирает хлопушку (титул, финальные титры, полноэкранные слайды).
- `class="slide act"` — межтитр-разделитель акта. `cover` — титул. `credits` — финальные титры. Остальные классы (`speaker`, `pot`, `center`…) — это готовые раскладки основной презентации со своей разметкой. Новый контент проще делать конструктором (ниже), а не копировать эти раскладки.
- Порядок появления: элементам с классом `rv` задаётся `style="--i:N"` (0, 1, 2… — очередь анимации).
- Не вставляй в файл служебные узлы, их создаёт скрипт: `.slate`, `.blk-ctl`, `.rz`, `.cr-add`, `contenteditable`. Классы `active/run/intro/standby/armed` тоже ставит скрипт. При сохранении он всё это вычищает, поэтому в исходнике этого быть не должно.

## Слайд-конструктор

Пустой конструктор (так его создаёт кнопка «＋ Слайд», функция `addSlide()`):

```html
<section class="slide free" data-act="Акт I">
  <header class="hd rv"><h2>Заголовок слайда</h2></header>
  <div class="blocks rv" style="--i:1"></div>
</section>
```

Наполненный — это `.blocks` со списком элементов. Каждый элемент — обёртка `.blk` с типом:

```html
<div class="blocks rv" style="--i:1">
  <div class="blk" data-type="lead"><p class="lead">Текст</p></div>
  <div class="blk" data-type="drivers" data-tone="green">
    <div class="drivers">
      <div class="drv"><p class="no">ЛИНИЯ 01</p><h3>Название</h3><p class="val">+00 млн</p><p class="cap">подпись</p></div>
      …
    </div>
  </div>
</div>
```

Правила:

1. **Тип = ключ в `BLOCKS`.** Внутренность `.blk` — ровно `BLOCKS[type].html` из `kino/src/deck.html` (ищи `const BLOCKS = {`). Не выдумывай разметку: скопируй шаблон оттуда и замени тексты. Типы: `lead`, `segs`, `drivers`, `tiles`, `marquee`, `table`, `facts`, `questions`, `gal`, `speakers`, `podium`, `pitch`, `script`, `fork`, `total`.
2. **Пункты.** У типа с полем `item` внутри повторяются однотипные узлы (`.drv`, `.tile`, `tr`, `figure`, `li`…). Чтобы добавить пункт, скопируй последний такой узел, чтобы убрать — удали его. Кнопки ＋/− в браузере делают то же самое.
3. **Порядок элементов** — это порядок `.blk` внутри `.blocks`, сверху вниз.
4. **Цвет акцента** (для типов с `tone`) — атрибут `data-tone` на `.blk`: `gold | green | coral | steel | ink`, без атрибута = по умолчанию.
5. **Две колонки:** `<div class="blocks two">`. Элементы раскладываются по сетке слева направо. Граница колонок — `style="--split:60%"` на `.blocks` (20–80%, по умолчанию 50%). Не называй переменную `--a`: это имя занято.
6. **Ширина элемента:** `style="width:70%"` на `.blk` (20–100%, центрируется). Нет атрибута — во всю ширину.
7. **Ширина колонок внутри элемента:**
   - у сеток (`drivers, tiles, marquee, facts, pitch, podium, gal, segs`) — `style="grid-template-columns:minmax(0,1.4fr) minmax(0,0.8fr) …"` на внутреннем контейнере (`.drivers` и т.п.). Число `minmax` должно совпадать с числом пунктов, иначе скрипт сбросит раскладку;
   - у таблицы — `style="width:NN%"` на ячейках `th` первой строки (столбцы добавляются и убираются копированием последней ячейки в каждой `tr`).
8. **Числа-счётчики:** у элементов с классом `count` значение дублируется в `data-final` (`<p class="v count" data-final="ТОП 1">ТОП 1</p>`). Меняешь текст — меняй и `data-final`, иначе после анимации покажется старое значение.
9. **Фото:** `<div class="photo" data-label="Фото"></div>` — пустая рамка. Снимок хранится как `class="photo has-img" style="background-image:url(data:…)"`. Пользователь вставляет его сам кликом в режиме правки. Внешние URL не годятся: файл должен работать офлайн.
10. **Высота не твоя забота.** `fitFree()` уменьшает `.blocks` через `zoom`, пока содержимое не влезет в кадр. Но если zoom падает ниже ~0.6, текст становится мелким, и лучше разбить контент на два слайда.

Редактируемым скрипт делает любой `h1–h4, p, li, td, th, figcaption span, .e` без вложенных блоков (`EDITABLE` в `deck.html`). Обычный текст оборачивай в эти теги, тогда пользователь сможет его поправить.

## Фон слайда

Атрибут на `<section>`: `data-bg="spot|curtain|film|night|amber|board|black"`, без атрибута — фон по умолчанию. Своё фото: `data-bg="photo" style="background-image:linear-gradient(rgba(11,10,9,.6),rgba(11,10,9,.84)),url(data:image/jpeg;base64,…)"`. Затемняющий градиент обязателен.

## Типовые операции

- **Добавить слайд:** вставь `<section class="slide free" …>` в нужное место `#stage` (для шаблона — в `src/template.html`), наполни `.blk` по `BLOCKS`, затем `node kino/build.mjs`.
- **Отредактировать текст:** меняй текст прямо в тегах. Структуру и классы не трогай, у счётчиков синхронизируй `data-final`.
- **Удалить слайд:** удали `<section>` целиком. Номера сцен пересчитаются сами.
- **Переставить:** перенеси `<section>` (или `.blk` внутри `.blocks`).
- **Новый тип элемента:**
  1. Добавь запись в `BLOCKS`: `имя: { html: '…', item: 'селектор пункта', tone: 1, cols: 1 }`. `item`, `tone` и `cols` указывай только если нужны: ＋/− пункт, смена цвета, ＋/− столбец таблицы.
  2. Добавь кнопку в панель `#kit`: `<button data-add="имя">Название</button>`.
  3. Если внутри сетка карточек, добавь её класс в `GRID`, чтобы появились ручки ширины колонок.
  4. Стили — отдельная задача, этот скил их не описывает.

## Проверка

После сборки открой файл в headless Chromium. Playwright предустановлен, путь к браузеру — `/opt/pw-browsers/chromium*/chrome-linux/chrome`. Затем:

- нет `pageerror`;
- открой файл сразу на нужном слайде (`файл.html#N`, нумерация с 1) или нажми `e` — это снимает экран «Мотор!» — и затем меняй `location.hash`;
- у `.free .blocks` проверь `style.zoom` (пусто или ≥ 0.6) и что `scrollWidth <= clientWidth` (нет вылезания по ширине);
- в режиме правки (`e`) у каждого `.blk` есть `.blk-ctl`. В сохранённом файле (Ctrl+S, перед этим `window.showSaveFilePicker = undefined`, чтобы файл ушёл в загрузку) нет `.blk-ctl`, `.rz`, `contenteditable`.
